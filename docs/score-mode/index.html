Score Mode

Ideas for turning StreamBuddy from "a grid of streams" into "the best seat for a whole slate of games." The scores feed already tells us which games matter right now. These ideas put that to work while keeping almost all of it in the browser, so Vercel costs stay where they are.

Your open question

Should a click add the game or replace the main one?

Both, depending on how the user gets there. People reach for the scoreboard for two different reasons: "something is happening over there, show me" and "I want one more game going." Give each its own gesture, and make the quick one undoable so it never feels risky.

Recommendation

Click → small menuWatch now, Add to layout, Replace tile 1–N, Pin score card, Follow team. The toggle above the wireframe lets you try the other defaults.
Watch now = promote, don't deleteThe new game becomes main and the old main slides to slot 2. Something only drops off if the layout is full, and the toast offers Undo.
Drag onto a tile = replace that tilePrecise and visual. Dragging a game that is already on screen swaps the two tiles.
Shortcuts for power usersEnter watch now, Shift+Enter add, P pin card. Double-click a row also watches.

Implementation note: the app already keeps iframes in a fixed DOM order and places them with CSS order, so "promote to main" can reuse handleMakeMain without reloading any player.

Scoreboard drawer

Score bugs on tiles

A small score overlay on each stream. Many ppv streams crop or delay the broadcast graphic, and small tiles make it unreadable. One toggle for all tiles, plus a per-tile override.

Browser onlyS

Bottom ticker

A crawl across the bottom in fullscreen with every live score, followed teams first. Pauses on hover; tapping a score opens the same game menu.

Browser onlyS

Game Pulse

A 0–100 "how much does this game matter right now" score from margin, time left, upset, overtime, teams you follow and fantasy players. It sorts the drawer and powers alerts and the auto-director. Formula below.

Browser onlyS

Spoiler shield

ppv streams often run 30–90 s behind live, so a score bug can show a touchdown before you see it. Option 1: hide scores for games on screen. Option 2: a delay slider that shows scores from N seconds ago, using snapshots the browser keeps.

Browser onlyS

Smart layouts

Saved layouts hold rules instead of URLs, because embed URLs change every game. "Main: the Seahawks game. PiP: the closest NFL game. Cards: my NBA teams." Loading a layout fills it from whatever is live.

Share a setup link

Put the smart layout in the URL hash: #l=pip;nfl:SEA;hot:nfl;card:nba:OKC. A friend opens it and gets the same setup with the streams that are live for them. No backend.

Next

Bigger, still cheap.

Close-game alerts

A toast, plus a browser notification if allowed, when a game crosses a Pulse threshold: a team you follow in a one-score game late, any game going to overtime, an underdog leading in the fourth. Watch now and Pin card buttons sit right in the alert. Works while a StreamBuddy tab is open.

Browser onlyM

Auto-director

RedZone-style: the main slot follows the hottest game. It only switches when the gap is big enough and the cooldown has passed, and it never moves a main you've locked. Every switch comes with an Undo and a Lock button.

Browser onlyM

Game detail panel

Open a game for box score, leaders, scoring plays and a win-probability sparkline. ESPN's summary is about 600 KB, so a small /api/game?id= function trims it to ~15 KB and caches it at the CDN for 60 s.

CDN-cached functionM

"What you missed"

When you switch a game into main, a short strip lists the scoring plays since you last had it on screen. Comes from the same trimmed summary.

CDN-cached functionS

Auto-join followed teams

When a followed team's game starts and a stream appears, add it to the layout or show a "Your game is on" toast. A "Remind me" button builds an .ics calendar file in the browser.

Browser onlyS

Tonight timeline

A horizontal timeline of today's games by start time, so you can see overlaps and plan which games share the screen. Click a block to pre-load it into a smart layout.

Browser onlyS

Fantasy overlay

Import a Sleeper league by username, with no login needed. Badges show "3 of your players" on games, Pulse gets a boost, and the detail panel shows your players' lines. Details in the Fantasy section.

Dream

Worth designing toward; each one introduces a real running cost.

Phone as remote

Scan a QR code on the TV or desktop and your phone becomes the scoreboard: tap a game there and it swaps in on the big screen. Needs a realtime channel between the two devices. Supabase Realtime's free tier covers this if accounts already use Supabase.

Background push alerts

Close-game alerts with the tab closed. Needs a job that checks scores every minute on game days, stored push subscriptions, and alert rules per user. Vercel Hobby cron only runs daily, so this would live in Supabase (pg_cron + an edge function).

The relevance algorithm

Game Pulse

One number answers "should I be looking at this game right now?" It runs in the browser on every scores refresh. Every input is already in the feed or one field away, and the user's follows and fantasy roster only add bonuses. Without an account it still works for everyone.

close = max(0, 1 − |margin| / scale) scale: NFL 17 · NBA 15 · NHL 3 · soccer 3 late = share of regulation played 0 at kick-off, 1 at the final whistle or in OT base = close × (0.35 + 0.65 × late) a tie in the 1st is interesting; a tie in the 4th is very interesting bonus + 0.15 underdog (by pre-game line) leading after halftime + 0.20 overtime + 0.10 red zone / power play / penalty kick (from situation) + 0.25 a team you follow + 0.05 per fantasy starter in the game, max 0.15 pulse = min(100, round(100 × (base + bonus))) pre-game: 10 inside 15 min of start, +25 if followed · final: 0

Below, the same formula scoring the wireframe's games as they tick. The scale constants are a first guess: one score in football, two possessions in basketball. They are easy to tune once real games show how it ranks.

Accounts & infrastructure

Accounts without a backend to babysit

Everything a user would save fits in one small JSON document: follows, smart layouts, preferences, fantasy links. Make that document the unit everywhere. It lives in localStorage today, gets a share link and export next, and syncs to an account later without changing shape. With accounts, the browser talks straight to the auth and database provider, so Vercel never sees the traffic.

Phase 0 · now

Local profile

  • One versioned streambuddy.profile key replaces the loose keys
  • Follow teams and leagues, smart layouts, prefs
  • Export or import as a code; share layouts by URL
$0. Matches the ROADMAP plan.
Phase 1 · accounts

Sign in to sync

  • Supabase Auth: magic link and Google
  • One profiles row per user holding the JSON doc, protected by row-level security
  • Load on sign-in and merge with local; debounced writes (≥ 5 s)
  • Accounts stay optional and everything works signed out
$0 on the free tier (50k monthly users, 500 MB). A 5 KB doc means 10k users ≈ 50 MB. Free projects pause after a week without traffic; Pro is $25/mo if that bites.
Phase 2 · realtime

Remote & rooms

  • Supabase Realtime broadcast channel per pairing or room
  • Messages are small commands like {watch: "nfl:SEA"}, not video
Free tier covers small use; concurrent connections are the limit to watch.
Phase 3 · push

Alerts with the tab closed

  • pg_cron every minute on game days → edge function → ESPN
  • Compare against stored alert rules, send Web Push
The first piece that costs real compute. Only build it once people are asking for it.

The whole database

create table profiles (
  user_id uuid primary key
    references auth.users on delete cascade,
  doc jsonb not null,
  updated_at timestamptz not null default now()
);

alter table profiles enable row level security;

create policy "own profile" on profiles
  for all using (auth.uid() = user_id)
  with check (auth.uid() = user_id);

Merging local and synced docs: take the union of follows, keep layouts by name with the newer one winning, and let the newer updatedAt win for prefs. Firebase Auth with Firestore is an equal alternative that never pauses. Supabase is the pick because realtime and cron come in the same box for phases 2 and 3.

ESPN's endpoints also allow browser requests directly (open CORS, checked today), which would take Vercel out of scores completely. Keeping the proxy is the safer default: one cached request per region instead of one per viewer, and one place to fix things if ESPN changes.

Small changes to api/scores.js

Fields to add to the feed

All of these are already in the scoreboard response trimEvent reads, so they add bytes but no extra requests.

  • period and clockSec from status.period / status.clock so Pulse doesn't parse "4th 8:18"
  • teams[].color for score bugs and cards without hotlinking logos
  • teams[].record a drawer subtitle ("6-2"), also handy for upset logic in soccer
  • situation while live: possession, down & distance, red zone for the possession dot and the RZ bonus
  • favorite: which team the pre-game line favours parsed once on the server from odds.details
  • More leagues: NCAAF, NCAAB, Champions League, MLB in season more ESPN fetches per refresh, no more function runs
  • A ?fast=1 variant with s-maxage=30 polled only while the drawer, cards or ticker are showing
